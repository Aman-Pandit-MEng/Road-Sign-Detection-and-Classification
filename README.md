# Road Sign Detection (traffic_sign)

This folder contains a simple road/traffic sign detection dataset and model artifacts used to train and evaluate a detector.

Summary
- `traffic_sign/` — dataset and helper files describing the train/test/valid images and labels.
- `traffic_sign/model/` — model code and training scripts (contains `train.py`, `infer.py`, and `requirements.txt`).
- `test/` — example `images/` and `labels/` used for testing/inference.
- `traffic_signs_full/` — outputs from a completed training run (graphs, `args.yaml`, `results.csv`, and `weights/` with `best.pt` and `last.pt`).

Quick goal
Create, train, and evaluate a road sign detection model with the provided dataset and view the results saved in `traffic_signs_full/`.

Prerequisites
- Python 3.8+ (use virtualenv or conda)
- pip
- Git (to manage and push changes)

Install dependencies
1. Switch to a virtual environment (recommended):

   python -m venv .venv
   source .venv/bin/activate

2. Install Python requirements. The model folder includes a `requirements.txt` that should list dependencies used for training/inference. From repository root:

   pip install -r traffic_sign/model/requirements.txt

If you prefer to inspect or edit dependencies, open `traffic_sign/model/requirements.txt` first.

Dataset layout (expected)
- `traffic_sign/train/images/` and `traffic_sign/train/labels/` — training images and label files
- `traffic_sign/valid/images/` and `traffic_sign/valid/labels/` — validation images and label files
- `traffic_sign/test/images/` and `traffic_sign/test/labels/` — test images and labels

Label format
The repository uses per-image label files (text) placed alongside images in `labels/`. Each label line typically contains: class_id x_center y_center width height (normalized) — confirm in `traffic_sign/data.yaml` or the `train.py` code.

Training
1. Inspect `traffic_sign/data.yaml` to ensure the dataset paths and class names are correct.
2. Run the training script in `traffic_sign/model/`. The project includes `train.py`. Exact CLI flags depend on that script; a typical usage pattern is:

   python traffic_sign/model/train.py --data traffic_sign/data.yaml --epochs 50 --img 640 --batch 16

Notes:
- If `train.py` accepts a `--weights` flag you can pass an existing `.pt` file to fine-tune or start from pretrained weights.
- Training outputs (loss/metrics graphs, results CSV) are commonly written to a `runs/` or `traffic_signs_full/` directory — check the script's `--project`/`--save` options.

Using the provided trained model
- `traffic_signs_full/` contains the results from a completed training run:
  - `args.yaml` — training configuration used for that run
  - `results.csv` — numerical results (mAP, precision, recall, loss values)
  - `weights/last.pt`, `weights/best.pt` — trained model weights

Inference / evaluation
1. Use `traffic_sign/model/infer.py` (or the project's inference script) to run inference with the trained weights. Example:

   python traffic_sign/model/infer.py --weights traffic_signs_full/weights/best.pt --source test/images --output runs/detect/predict

2. Inspect the `runs/detect/predict/` (or configured output folder) for predicted images, and open `traffic_signs_full/results.csv` for aggregate metrics and graphs inside the `traffic_signs_full/` folder.

Tips and next steps
- Confirm the exact CLI arguments of `train.py` and `infer.py` before running — open them to check accepted flags.
- If you want to visualize training curves, open the saved images/plots in `traffic_signs_full/` or `runs/` generated by the training script.
- To retrain from scratch, delete or move the `traffic_signs_full/weights/` files and re-run the training script.
